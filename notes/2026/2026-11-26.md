### [Change Request: Revisit policies about accepting new language features](https://github.com/eslint/eslint/issues/21453)

**TSC Summary:** There are mismatches between ECMAScript features and `ecmaVersion` years, specifically for Temporal and Explicit Resource Management. @nzakas proposed stopping the addition of yearly `ecmaVersion` values and encouraging users to use `3`, `5`, or `"latest"` instead.

* @mdjermanovic supported the proposal, noting that grouping features by specification years is not very useful and that users can use `eslint-plugin-es-x` to restrict syntax, globals, and methods on globals.
* @fasttime suggested asking @nzakas to open an RFC to evaluate the changes. He agreed that `eslint-plugin-es-x` would help users avoid unsupported features without yearly `ecmaVersion` values.

**Resolution:** The TSC agreed to proceed with the proposal and ask @nzakas to open an RFC to evaluate the changes.

**Action Items:**
- @nzakas will:
  - Open an RFC to evaluate the proposed `ecmaVersion` changes.

### [Bug: `Custom getLoc() method must be implemented in the subclass.` error when using GFM language and error found for markdown/no-missing-label-refs](https://github.com/eslint/markdown/issues/619)

**TSC Summary:** The GFM autolink remark plugin may produce nodes without a `position` property, while rules expect it to exist, for example when using `sourceCode.getText()`. The issue was reported upstream and closed as cannot fix. In a related [PR discussion](https://github.com/eslint/markdown/pull/620#issuecomment-3887287168), @nzakas suggested addressing the problem in `getLoc()` so that all rules can benefit, rather than handling missing positions in individual rules.

* @mdjermanovic suggested adding missing `position` properties directly to the AST nodes. @fasttime agreed that the issue should be handled in the language plugin, either in `getLoc()` or earlier when the AST is generated, rather than in the rules.
* @mdjermanovic noted that many rules access `node.position` directly and suggested evaluating whether the AST can be updated in `MarkdownSourceCode#traverse()`. @fasttime agreed and suggested evaluating other alternatives if that is not feasible.

**Resolution:** The TSC agreed that the preferred direction is to update the AST in the Markdown language plugin, possibly in `MarkdownSourceCode#traverse()`, so that `node.position` is always set.
